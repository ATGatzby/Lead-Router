Getting Started with Lead Router

Lead Router is a self-hosted Salesforce lead routing engine. You deploy it on your own server — your data never leaves your infrastructure. No per-API-call fees, no vendor lock-in.

How it works Salesforce triggers fire when records are created or updated. Those events hit your routing engine, which evaluates your rules and assigns records to the right rep, team, or queue — in real time.

What you'll need

VPS with Docker Any Linux server — Hetzner, DigitalOcean, Vultr, AWS, or bare metal. 2GB RAM minimum.
Salesforce Org Production or sandbox org. You'll install a managed package that sends trigger events.
Node.js 20+ Required on your local machine to run the CLI installer. Not needed on the server.
Two HTTPS Domains One for the web dashboard, one for the engine (e.g. app.acme.com + engine.acme.com).
Architecture at a glance The CLI deploys 5 Docker containers: Web (Next.js dashboard), Engine (Fastify routing engine), PostgreSQL, Redis, and Caddy (reverse proxy with auto-HTTPS via Let's Encrypt).

Deploy with the CLI

The CLI wizard handles everything: generating config, SSHing into your server, pulling Docker images, and verifying health.

Terminal
$ npx @lead-routing/cli@latest init

The 9-step wizard

License validation

Enter your Pro license key, or press Enter to continue with the free tier. The CLI shows your tier limits.

Install Salesforce package

The CLI opens a browser link to install the managed package in your Salesforce org. Click "Install for All Users" in Salesforce. You can also do this later from the web app.

Prerequisites check

Verifies Node.js 20+ is installed on your local machine.

SSH connection

Enter your VPS hostname/IP, SSH port (default 22), username (default root), and password or private key path. The CLI tests the connection before proceeding.

App configuration

App URL — public HTTPS URL for the web dashboard (e.g. https://routing.acme.com).
Engine URL — public HTTPS URL Salesforce will call (e.g. https://engine.acme.com).
Admin email + password — creates the first login user for the web app.
Database and Redis are managed automatically via Docker.

Generate config files

Creates docker-compose.yml, .env.web, .env.engine, Caddyfile, and lead-routing.json in a local ./lead-routing/ directory.

Remote setup

Uploads all config files to your VPS via SFTP, then runs docker compose pull to fetch the latest images from the container registry.

Start services

Runs docker compose up -d on the server. Caddy auto-provisions Let's Encrypt TLS certificates. The web container runs database migrations and seeds the admin user on first boot.

Health verification

Polls both HTTPS endpoints (up to 2 minutes) until they return healthy. Once verified, you'll see your dashboard URL and admin credentials.

DNS must be configured first Point your App URL and Engine URL domains to your VPS IP address before running the CLI. Caddy needs DNS to resolve to provision TLS certificates.
Interrupted deploy? Run lead-routing init --resume to skip config generation and re-attempt the remote setup and health check.

Connect Salesforce

After deployment, log into your web app and connect your Salesforce org.

Log into the dashboard

Open your App URL and sign in with the admin email and password you set during deployment.

Go to Integrations → Salesforce

Click Connect Salesforce. You'll be redirected to Salesforce to authorize the OAuth connection. Grant access to complete the flow.

Deploy the managed package

If you didn't install the package during CLI setup, click Deploy Package from the Salesforce integration page. This installs Apex triggers, custom settings, and the onboarding wizard.

Configure objects

Toggle which Salesforce objects to route: Lead (free), Contact, Account, and Opportunity (Pro). Click Save Configuration.

Sync fields

Click Sync Fields to pull your custom fields from Salesforce. These fields become available in routing rule conditions.

License Users

Only licensed users can be assigned records through routing. Navigate to License Users in the sidebar to manage who gets routed to.

5 licensing methods

Individual Select specific users one by one
By Role License all users in a Salesforce role
By Profile License all users with a profile
By Queue License queue members as routing targets
Custom Field License by any custom field value

The seats counter at the top shows how many seats you've used vs. purchased. Free tier includes 5 seats; Pro is unlimited.

Bulk actions Use the bulk action bar to assign or revoke licenses for multiple users at once.

Create Teams

Teams group licensed users for round-robin or weighted distribution. Navigate to Teams in the sidebar.

Create a team

Click New Team, give it a name and optional description.

Add members

Search for licensed users and add them. You can pause or remove members at any time.

Choose distribution mode

Round-Robin — cycles through members equally, one after another.
Weighted — assigns based on percentage weights (e.g., a senior rep gets 40%, a junior rep gets 10%). Weights auto-normalize to 100%.

Slot preview In weighted mode, a visual pie chart shows how the next 20 assignments will be distributed across team members.

Build Routing Rules

Navigate to Routing Rules and click New Route. Choose between two types:

⚡ Real-Time Route Triggers on record insert or update in Salesforce. Routes instantly as records are created/modified.
🔍 Scheduled Route Runs on a schedule (daily, weekly, monthly). Queries Salesforce using search criteria and routes matching records in batch.

Step types

Trigger (Real-Time) or Search Trigger (Scheduled) — Defines when the rule fires. For real-time: choose insert, update, or both, and optionally set trigger conditions to filter before routing. For scheduled: define SOQL search criteria, frequency, and batch size.

Match (optional) — Checks for existing records before routing. Configure which objects to search (Leads, Contacts, Accounts) and matching fields:

  • Email — exact match
  • Phone — normalized match (strips formatting)
  • Domain — extracts domain from email, matches against Account website
  • Company Name — three matching modes:
    • Strict — exact match after normalizing (removes Inc, LLC, Corp, etc.)
    • Fuzzy — Levenshtein similarity + 400+ known abbreviation pairs (IBM ↔ International Business Machines)
    • AI Smart PRO — semantic matching via your configured AI provider

When a match is found, choose an action: merge with the matched record, assign to its owner, assign to a custom user/team, or skip routing.

Filter + Assign — Create multiple branching paths with conditions (e.g., "Industry = Technology → assign to Tech Team"). Each path can assign to a specific user, team (round-robin), or Salesforce queue.

Default Owner — Fallback assignment if no filter paths match. Every rule should have one.

Dry run mode Toggle "Dry Run" on any rule to simulate routing without actually changing record ownership in Salesforce. Check the Activity tab to see what would have happened.

Activity & Monitoring

The Activity section has five sub-tabs for full visibility into your routing operations.

Routing History

A paginated log of every routing event. Each row shows the record ID, object type, rule name, assignee, duration, and status:

SUCCESS FAILED UNMATCHED RETRY MERGED COOLDOWN

Expand any row to see the full decision trace — which rule matched, which path was taken, and why.

Assignment Stats

Per-rep distribution breakdown. See how many Leads, Contacts, and Accounts each rep received over a given period (today, this week, this month). Sortable bar chart.

Failed Routings

Shows records that failed or are in retry status. Retry re-enqueues individual records; Retry All bulk re-enqueues everything. Dismiss removes entries from the list.

Audit Log

Tracks every admin action: rule creation, team changes, user licensing, settings updates. Each entry shows who did what, when, and a before/after state diff.

Record Journey

Search by any Salesforce Record ID (15-18 characters) to see every routing event for that specific record. The timeline shows trigger type, rule name, path taken, assignee, and status for each event.

System health

AI Assistant PRO

A natural language chat interface for querying your routing data, analyzing performance, and getting optimization recommendations.

What it can do

  • Query routing data in plain English ("Which rule routed the most leads this week?")
  • Performance analysis and anomaly detection
  • Conversion and pipeline insights
  • Rule optimization recommendations

Configuration

Go to Settings → AI Assistant and select your provider:

  • Claude (Recommended) — Sonnet 4.5
  • OpenAI — GPT-4o, GPT-4o mini, o3-mini
  • Gemini — 2.5 Flash, 2.5 Pro
  • Custom — any OpenAI-compatible endpoint

Paste your API key and select a model. Your key is stored encrypted (AES-256-GCM) and never leaves your server.

Settings

The Settings page has four tabs.

General

Reconnect Salesforce — re-authenticate if your OAuth token expires. Sync Webhook Secret — pushes the webhook secret to Salesforce custom settings (needed if you changed it).

Webhooks

Set a notification webhook URL to receive a POST request on every successful routing. Useful for Slack, WhatsApp, or custom integrations. Available variables:

  • {{rep_name}} — assigned rep's name
  • {{object_type}} — Lead, Contact, or Account
  • {{record_id}} — Salesforce record ID
  • {{rule_name}} — which rule matched
  • {{timestamp}} — when it was routed
  • {{record_url}} — direct link to the Salesforce record

AI Assistant

Configure your AI provider and model (see AI Assistant section above).

License

View your current tier, usage (rules, seats, objects), and license details (key, activation date, expiry). Activate or deactivate a license key from here. See Upgrading to Pro below.

Troubleshooting

DNS not resolving

The CLI warns if your domain doesn't resolve. Make sure your A record points to your VPS IP. DNS propagation can take up to 48 hours, but usually completes in minutes. You can continue the wizard — Caddy will retry certificate provisioning.

SSH connection failed

Double-check your hostname, port, username, and password. If using a private key, ensure the path is correct and the key has proper permissions (chmod 600). Some VPS providers disable password auth by default — check /etc/ssh/sshd_config.

Docker not running on VPS

The CLI checks for Docker during remote setup. If Docker isn't installed, install it with: curl -fsSL https://get.docker.com | sh. Make sure the Docker daemon is running: systemctl start docker.

Let's Encrypt rate limit

Let's Encrypt allows 5 certificates per registered domain per 168 hours. If you hit this limit during repeated deploys, use different subdomains or wait for the window to reset. Caddy caches existing certificates in a Docker volume.

Salesforce OAuth callback mismatch

The OAuth callback URL must match SFDC_REDIRECT_URI in your .env.web exactly. This is set to {APP_URL}/api/auth/sfdc/callback during init. If you change your App URL, update .env.web and recreate the web container.

Health check times out

If the CLI's health check fails after 2 minutes, SSH into your VPS and check: docker compose logs web --tail 50. Common causes: Caddy can't reach Let's Encrypt (firewall blocking ports 80/443), database migration failure, or missing environment variables.

Still stuck? Run lead-routing doctor for a comprehensive health check, or check the container logs with lead-routing logs web or lead-routing logs engine.
