Implementation Guide

Everything you need to deploy Lead Router from zero to a working installation. Your data never leaves your infrastructure.

~25 minutes total

How it works

Lead Router installs as a self-hosted stack on your VPS. Salesforce triggers fire automatically when records are created or updated, sending them to the routing engine for instant assignment.

Salesforce
Apex Trigger fires
---> HTTPS POST
Routing Engine
Evaluates rules
---> REST API
Salesforce
Owner updated
Web Dashboard
Manage rules, view analytics

Prerequisites

  • VPS — Any Linux server (Ubuntu 20+, Debian 11+, CentOS 8+) with 1 vCPU, 2 GB RAM, 20 GB disk. Root SSH access required.
  • DNS — Two A records pointing to your VPS IP (e.g. app.acme.com and api.acme.com). SSL is provisioned automatically.
  • Salesforce — Enterprise, Developer, or Sandbox org with admin access.
  • Local machine — Node.js 20+ installed. The CLI runs from your machine and connects to the VPS via SSH.
  • Ports — Ports 80 and 443 open on the VPS (for HTTPS traffic and SSL certificate issuance).

Create DNS A Records

In your DNS provider, create two A records pointing to your VPS IP address:

TypeNameValueTTL
Aapp165.22.100.50300
Aapi165.22.100.50300
i
Replace 165.22.100.50 with your actual VPS IP. The app subdomain serves the web dashboard, api serves the routing engine that Salesforce calls.

An A record maps a domain name to an IP address. When someone visits app.acme.com, their browser looks up the A record to find the server's IP.

After adding the records, it can take 5-30 minutes for DNS to propagate. You can check propagation at dig app.acme.com from your terminal.

The CLI will automatically provision SSL certificates via Let's Encrypt once DNS is pointing correctly, so you don't need to worry about HTTPS configuration.

Salesforce Connected App

Create an OAuth Connected App so Lead Router can securely access your org.

Step-by-step

  1. In Salesforce, go to Setup → search "App Manager" → click New Connected App
  2. Fill in the basic info:
    • Connected App Name: Lead Router
    • API Name: Lead_Router (auto-filled)
    • Contact Email: your email
  3. Under API (Enable OAuth Settings), check "Enable OAuth Settings"
  4. Set the Callback URL to:
    https://app.acme.com/api/auth/sfdc/callback
    Replace app.acme.com with your actual app domain
  5. Add these OAuth Scopes:
    Access your basic information (api) Perform requests at any time (refresh_token, offline_access)
  6. Check "Require Secret for Web Server Flow"
  7. Click Save, then wait ~2 minutes for Salesforce to register the app
  8. Click "Manage Consumer Details" → verify your identity → copy the Consumer Key and Consumer Secret

The Callback URL must match exactly — including https:// and the path /api/auth/sfdc/callback. A mismatch will cause a redirect_uri_mismatch error during Salesforce login. Use https://test.salesforce.com as the login URL for sandbox orgs.

A Connected App is Salesforce's way of allowing external applications to authenticate via OAuth 2.0. It provides a Consumer Key (Client ID) and Consumer Secret that Lead Router uses to securely obtain access tokens for your org.

Your credentials are stored exclusively on your server — Lead Router never sends them to any third party.

Key controls:

  • Active / Paused — Toggle a member's status. Paused members are skipped during assignment (e.g. when someone is on PTO).
  • Reset Pointer — Resets the rotation back to the first member. Useful after adding or removing members.

Distribution types

Each team supports two distribution modes, selectable on the team detail page:

Equal Round Robin (default) — Every active member receives leads in strict sequential order, one each in turn. All members get an equal share.
Weighted Round Robin — Assign a weight to each member to control what proportion of leads they receive. For example, weights of 40/40/20 mean the first two reps each get 40% and the third gets 20%.
In weighted mode, use the sliders to adjust each member's weight. Toggle between Percentage (must sum to 100) and Points (must sum to 10) modes. Use the Equalize button to reset all weights to equal.
i
Reference teams in your routing rules by choosing "Round Robin" as the assignment type and selecting the team. The engine will cycle through active members — equally or by weight, depending on the team's distribution type.

Trigger Conditions

Filter records before they leave Salesforce — save API calls and reduce noise.

Pre-callout filtering

Trigger conditions let you define criteria that records must meet before the routing engine is called. This filtering happens inside Salesforce's Apex trigger, so records that don't match never leave your org.

How to set up

  1. Open a rule and click on the Trigger step in the canvas
  2. In the Trigger config sheet, scroll down to Trigger Criteria
  3. Add conditions using the condition builder — same UI as path conditions
  4. Conditions within a group are joined with AND. Multiple groups are joined with OR.
  5. Save the rule. Conditions are automatically synced to Salesforce as Route_Criteria__c records.

⚠
If no trigger criteria are defined, all records are sent to the engine (legacy behavior). Adding criteria is optional but recommended for high-volume orgs to reduce API usage.

Fuzzy & AI Matching

Match records using phonetic algorithms, similarity scoring, or AI-powered semantic comparison.

Three matching modes

When configuring the Match step, you can enable company name matching with one of three modes:

🎯
Strict
Exact normalized match only. "Acme Inc" = "acme"
🔮
Fuzzy
Levenshtein, Soundex, Double Metaphone + abbreviation dictionary
🧠
AI Smart
LLM-powered semantic matching with 3-layer alias cache

How fuzzy matching works

The fuzzy matcher runs a cascading resolution chain — it tries the fastest method first and only falls back to more expensive checks if needed:

  1. Exact normalized — Strip suffixes (Inc, LLC, Corp, Ltd, GmbH), lowercase, remove punctuation
  2. Abbreviation dictionary — ~85 common mappings (IBM → International Business Machines, HP → Hewlett Packard)
  3. Levenshtein similarity — Character-level edit distance, threshold ≥ 0.85
  4. Soundex match — 4-character phonetic codes
  5. Double Metaphone — Primary + alternate phonetic encodings

AI Smart mode

When AI Smart is selected, the system adds an additional resolution step after fuzzy matching fails:

  1. Alias cache check — L1 in-memory (1,000 entries, 1hr TTL) → L2 Redis (24hr TTL) → L3 Postgres (permanent)
  2. AI provider call — Sends company name pair to your configured LLM (Claude, OpenAI, Gemini, or custom endpoint)
  3. Cache result — Writes the AI's decision to all cache layers to avoid repeated calls
i
AI Smart mode requires an API key configured in Settings → AI. Rate limited to 10 calls/sec per org. If the AI is unavailable, it gracefully falls back to fuzzy matching.

Condition operators

You can also use fuzzy operators in path conditions:

OperatorAlgorithmUse case
fuzzy_equals Levenshtein ≥ 0.8 Typo tolerance — "Microsft" matches "Microsoft"
sounds_like Soundex + Double Metaphone Phonetic matching — "Smith" matches "Smyth"
similar_to AI Full resolution chain + AI Semantic matching — "JPMorgan" matches "JP Morgan Chase"

Troubleshooting

Common issues and how to resolve them.

Cause: DNS hasn't propagated yet, or ports 80/443 are blocked.

Fix:

  • Verify DNS: dig app.acme.com should return your VPS IP
  • Check firewall: ufw status (Ubuntu) — ports 80 and 443 must be open
  • Check Docker: SSH into VPS and run docker ps — all 5 containers should be running
  • Let's Encrypt rate limit: if you've provisioned too many certificates for the same domain, wait 1 hour

Cause: The callback URL in your Connected App doesn't match the one Lead Router is using.

Fix: In Salesforce Setup → App Manager → your Connected App → Edit, verify the Callback URL is exactly:

https://app.acme.com/api/auth/sfdc/callback

Replace app.acme.com with your actual app domain. No trailing slash.

Check these in order:

  1. Triggers active? — Open "Lead Router Setup" in Salesforce App Launcher and check Step 2 shows triggers are activated
  2. Rule matches? — Ensure your rule conditions match the Lead field values. Check the Activity page for "Unmatched" entries.
  3. Custom Settings configured? — In Salesforce Setup, search "Custom Settings" → "Routing Settings" → Manage. The Engine Endpoint should be https://api.acme.com
  4. Engine reachable? — Run curl https://api.acme.com/health from any machine. Should return {"status":"ok"}

Cause: The LeadRouterAdmin permission set isn't assigned to your user.

Fix: Salesforce Setup → Users → Permission Sets → Lead Router Admin → Manage Assignments → Add your user.

SSH into your VPS and use Docker logs:

Cause: The match mode is set to "Strict" (default) instead of "Fuzzy" or "AI Smart".

Fix:

  • Open the rule in the Route Builder and click the Match step
  • In the config sheet, look for Company Match Mode
  • Switch from "Strict" to "Fuzzy" or "AI Smart"
  • Save the rule — fuzzy matching takes effect immediately on the next routing event

If using AI Smart mode, also verify your API key is configured in Settings → AI and the provider is reachable from your server.

Check these in order:

  1. API key valid? — Go to Settings → AI and verify the key shows "Connected". Try disconnecting and reconnecting.
  2. Provider reachable? — SSH into your VPS and test: curl https://api.anthropic.com/v1/messages (or your provider's API). Firewall rules may block outbound HTTPS.
  3. Rate limited? — Check the engine logs for 429 responses. The AI assistant respects provider rate limits and will queue retries.
  4. Custom endpoint? — Verify the base URL includes the correct path prefix and that any custom headers (auth tokens) are correct.

Cause: The sync from web app to Salesforce Route_Criteria__c records failed silently.

Fix:

  • Check Salesforce connection — Go to Integrations and verify the Salesforce org shows "Connected". Reconnect if the OAuth token expired.
